# BambuMonitor 多账号设备聚合设计

日期：2026-08-13

## 目标

BambuMonitor 在同一个窗口中同时保存并连接多个拓竹账号，把这些账号绑定的打印机合并到现有设备控制台和摄像头墙中。

用户可以在添加账号时填写备注，也可以直接跳过并稍后修改。设备名称后显示账号标识：

- 有备注：`A2L01（公司）`
- 无备注：`A2L01（138****1234）`
- 同一序列号意外出现在多个账号：只显示一张设备卡，例如 `A2L01（公司 / 工作室）`

该能力同时适用于 Windows/macOS 桌面版和 Docker/NAS 版。升级后保留现有账号、登录状态、设备地址、摄像头设置和其他用户设置。

## 非目标

- 不恢复“启动多个独立程序实例”的方案。
- 不提供跨用户或公网共享账号的服务。
- 不改变拓竹账号本身的设备归属关系。
- 不把账号、手机号、邮箱或访问令牌写入普通日志、公开设备接口或通知负载。
- 不为每个账号创建独立控制台；所有设备仍在一个控制台中统一操作。

## 用户体验

### 首次使用

无账号时保留当前登录页。账号登录成功后可填写“账号备注（可选）”，也可选择跳过。跳过不会阻止同步设备，也不会在之后强制补填。

初次登录完成后进入控制台。用户以后通过“设置 → 账号”继续添加账号，不需要退出当前账号。

### 账号中心

“设置 → 账号”改为账号列表，每一项显示：

- 备注；未填写时显示脱敏账号
- 脱敏后的手机号或邮箱
- 当前状态：在线、同步中、需要重新登录或同步失败
- 该账号贡献的设备数量

每个账号提供以下操作：

- 修改备注
- 重新登录
- 删除账号

账号区顶部提供“添加账号”按钮。添加流程复用当前密码/验证码登录能力，备注输入位于登录成功后的确认步骤，并明确标注“可选，可稍后填写”。

删除账号前显示确认提示，并说明将从当前控制台移除仅属于该账号的设备。删除一个账号不会退出其他账号。删除最后一个账号后返回登录页。

### 设备名称与来源

打印机原始名称不写回拓竹云端，也不写入设备缓存。界面单独计算显示名称：

`原始设备名（账号标识）`

账号标识按以下优先级生成：

1. 非空备注
2. 脱敏账号

手机号保留前 3 位和后 4 位；邮箱保留首字符及域名。备注去除首尾空白，最长 40 个字符。空白备注等同于未填写。

同一设备归属多个账号时，按账号添加顺序列出不同的账号标识并去重，用 ` / ` 分隔。设备卡、摄像头卡、放大画面标题、通知文案和无障碍标签统一使用同一个显示名称函数。

## 数据模型

每个账号使用随机生成且不包含个人信息的 `accountId` 作为稳定主键：

```text
AccountRecord
  accountId       随机稳定 ID
  account         原始手机号或邮箱，仅保存于受保护存储
  accountMasked   可公开到本地界面的脱敏账号
  remark          可选备注，默认空字符串
  accessToken     访问令牌，仅保存于受保护存储
  username        拓竹 MQTT 用户名
  savedAt         登录保存时间
  updatedAt       备注或凭据更新时间
```

账号运行状态不持久化，由本次运行实时计算：

```text
AccountRuntimeState
  accountId
  connectionState   idle | syncing | connected | error | invalid
  errorCode          稳定、无凭据的错误类别
  syncedAt
  deviceCount
```

聚合设备的私有记录包含来源账号集合和每个来源提供的访问码。公开设备只暴露安全字段：

```text
AggregatedDevice
  dev_id
  name
  displayName
  accountIds          仅本地不敏感随机 ID
  accountLabels       已脱敏或备注后的显示标签
  现有遥测字段
```

访问令牌、原始账号、访问码和本地 IP 继续遵守当前私有字段投影规则，不进入浏览器公开响应、通知或普通日志。

## 存储与迁移

### 桌面版

桌面版把当前单账号文件迁移为版本化账号仓库。整个账号数组继续使用 Electron `safeStorage` 加密保护。

启动时若只有旧的 `bambu-auth-session.json`：

1. 读取并验证旧账号。
2. 生成一个随机 `accountId`，备注设为空。
3. 原子写入新的多账号仓库。
4. 重新读取并验证新仓库。
5. 仅在新仓库验证成功后删除旧文件。

迁移失败时继续保留旧文件并显示可恢复错误，不覆盖或清空现有登录。

### Docker/NAS 版

服务端加密会话存储从单个 `bambu` 记录迁移为 `accounts` 数组。现有浏览器会话仍代表访问这套本地 BambuMonitor 的权限，而不是某一个拓竹账号。

旧存储中的账号自动成为第一个账号，备注为空。添加、修改或删除其他拓竹账号不使当前浏览器会话失效。只有用户明确执行“退出 BambuMonitor”或删除最后一个账号时，才清理本地浏览器会话。

所有迁移采用当前存储层已有的原子写入、加密、权限和损坏隔离机制。不会要求用户因升级重新登录。

## 同步与连接架构

### 账号仓库

新增统一的账号仓库接口，桌面版和服务端提供相同行为：

- `listAccounts()`：只返回 `accountId`、备注、脱敏账号和状态
- `addAccount(credentials, remark)`：新增或更新同一个账号
- `updateRemark(accountId, remark)`
- `reauthenticateAccount(accountId, credentials)`
- `removeAccount(accountId)`
- `getPrivateAccount(accountId)`：仅主进程或服务端运行时可用

同一个原始账号再次登录时更新原账号的令牌和用户名，不创建重复账号；原备注保持不变，除非用户本次明确修改。

### 多账号设备运行时

设备运行时从单份凭据改为账号集合，但继续维护一个全局设备表和一个 MQTT 管理器：

1. 每个账号独立请求云端设备清单。
2. 请求采用有限并发，单个账号失败不会取消其他账号。
3. 所有清单按打印机序列号聚合。
4. 每轮全量云端同步后只执行一次局域网扫描。
5. 局域网结果按序列号补充 IP、型号和名称。
6. 每个序列号最多保持一个 MQTT 连接和一个摄像头源。

连接凭据选择规则：

1. 有可用本地 IP 和访问码时，优先本地 MQTT。
2. 否则使用该设备任一有效来源账号的中国区云端 MQTT 凭据。
3. 当前来源账号失效时，若重复设备还有其他有效来源，则切换来源而不删除设备。
4. 所有来源都失效时保留最后一次设备信息，并把连接状态标为需要关注。

局域网扫描不按账号重复执行，也不会把只在局域网发现、但不属于任何已登录账号的设备擅自加入控制台。

### 增量更新

添加账号后只同步新账号，再与现有全局设备表聚合；删除账号后只移除该账号的来源关系。仅当设备不再属于任何账号时，才断开 MQTT、释放摄像头并移除设备卡。

修改备注只更新账号标签和受影响设备的显示名称，不重连 MQTT、不重启摄像头，也不丢失遥测状态。

## 会话失效与错误处理

每个账号独立管理登录有效性：

- 某账号返回 401/403 时，仅将该账号标记为“需要重新登录”。
- 该账号独有设备保留最后一次数据并显示来源账号需要重新登录。
- 其他账号继续同步、重连和更新设备。
- 重新登录成功后只恢复该账号及其设备来源。

全局错误提示不再因为单个账号失效而把整个控制台退回登录页。设置按钮和账号列表显示需要处理的账号数量，设备卡仅在其所有来源账号都不可用且本地连接也不可用时显示连接异常。

添加账号过程中失败不会修改已有账号仓库或设备表。删除账号采用“先持久化、后修改运行时”的顺序；持久化失败时界面和连接保持原样。

## API 与事件

运行时接口增加账号维度：

- 列出账号
- 添加账号
- 修改备注
- 重新认证账号
- 删除账号
- 刷新一个账号或全部账号

设备快照继续按当前单一列表发送，但设备包含安全的账号标签信息。新增账号事件用于局部刷新账号中心：

- `accounts.snapshot`
- `account.updated`
- `account.invalid`
- `account.removed`

Docker 版所有账号修改请求继续要求同源、有效浏览器会话和 CSRF。桌面版通过受限 preload IPC 暴露同等操作。任何公开接口均不返回访问令牌、访问码或原始未脱敏账号。

## UI 适配

账号中心沿用现有设置面板的紧凑布局，不新增独立营销页或复杂向导。完整、紧凑和迷你窗口保持现有信息密度：

- 完整窗口显示带账号标识的设备名称。
- 紧凑窗口在名称空间不足时对整个显示名称省略，并通过提示显示全名。
- 迷你窗口保留汇总信息，不强行展示账号列表。
- 摄像头墙和放大画面使用同一设备显示名称。

账号备注不直接拼接到持久化的打印机 `name` 字段，避免备注变更造成设备身份变化、缓存错配或向拓竹云端写回。

## 测试策略

### 单元测试

- 可选备注的规范化、长度限制和显示优先级
- 手机号和邮箱脱敏
- 同一账号重复登录更新而不重复添加
- 设备按序列号聚合及标签去重、排序
- 修改备注不触发设备重连
- 删除一个来源不删除仍属于其他账号的设备
- 单账号失效不清空其他账号和设备
- 每个序列号只有一个 MQTT 连接和摄像头源

### 迁移测试

- 桌面版旧单账号文件迁移且登录状态保留
- NAS 加密单账号存储迁移且浏览器会话保留
- 新存储写入或验证失败时旧数据不删除
- 多账号存储重启后账号顺序、备注和凭据保持
- 日志和磁盘明文扫描不出现令牌或原始账号

### 集成测试

- 两个账号登录后设备在一个快照中出现
- 重复序列号只产生一张设备卡和一条 MQTT 连接
- 一个账号 401、另一个账号继续实时更新
- 添加、改备注、重新登录、删除的 API/IPC 行为一致
- Docker 的 CSRF、会话和公开字段投影仍然有效

### 界面测试

- 无账号、单账号、多账号、失效账号和重复设备状态
- 备注为空时使用脱敏账号
- 完整、紧凑、迷你、摄像头墙和放大画面不溢出
- 键盘焦点、按钮标签、确认提示和错误信息可访问

## 验收标准

1. 同一窗口可保存并同时连接至少 10 个拓竹账号。
2. 添加账号时备注可完全跳过，并可在设置中稍后修改。
3. 所有账号设备在一个列表中显示，名称遵循备注优先规则。
4. 相同序列号只显示一次，且只建立一条状态连接和一个摄像头源。
5. 任一账号失效、删除或同步失败不影响其他账号。
6. 旧桌面版和旧 NAS 版账号自动迁移且无需重新登录。
7. 访问令牌、访问码和原始账号不进入普通日志、公开接口或通知。
8. 现有摄像头、拖动缩放、通知、窗口模式和 NAS 访问行为无回归。
